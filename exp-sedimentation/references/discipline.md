# 记忆纪律（记什么、不记什么、红线、查重、回报）

> 纪律是本 skill 的核心。工具（exp-lite.mjs / 插件守卫）只是把纪律变成可执行的检查；
> 没有工具时，纪律照样生效——写入前把本文件过一遍。

## 1. 值得记（命中任意一条就记）

| 类型 | 例子 |
| --- | --- |
| 踩过的坑与**根因** | “PowerShell 拼中文文件名乱码” + 根因（编码/管道），不是“我试了三次才成功” |
| 验证过的命令 / 参数 / 路径 | 实跑通过的命令行、关键参数取值、本机固定路径 |
| 方案取舍与理由 | 选 A 不选 B 的判断依据、代价、适用边界 |
| 环境事实 | 本机版本、代理形态、硬件能力、网络拓扑等“换了机器就不成立”的事实 |
| 用户偏好 | 用户明确要求的格式、语气、交付方式、禁用项 |

判据一句话：**下个项目还会用上吗？** 会 → 记；不会 → 不记。

## 2. 不值得记（命中任意一条就不记）

- 过程叙述、流水账：“这次我先干了 A 又干了 B……”“今天完成了……”
- 能从文件、代码、git 历史重新推出的内容（写了也是过期副本）。
- 临时状态：任务进度、半成品结论、“下一步打算做……”。
- 一次性的中间报错与调试过程（只留**根因与最终做法**）。
- 与本领域无关的闲聊、猜测、未经验证的推断（推断要标注“待验证”，且不入库）。

## 3. 红线（零容忍，写入即拒绝）

- **绝不写密钥、token、密码、私钥、cookie、API Key 的值**——记忆库随每次请求离开本机。
- 只写“**凭据放在哪里**”：如“token 存在环境变量 `XXX_TOKEN` / 某配置文件，用前现读”，绝不写值。
- 八类可疑模式入库前必扫：`sk-`、`AKIA`、`ghp_`、`Bearer`、`password=`、`token=`、`passwd=`、`secret=`。
- 命中红线 → **拒绝写入并报错**，只报模式名与行号，不回显疑似值；改写成“凭据放在哪里”后再入库。
- 疑似脱敏但仍是值的东西（如 `sk-****`）也不要写，写成“key 前缀 sk-，完整值在 XX 处”。

## 4. 记现状，不记变迁史

- 不写“已卸载/不再使用/已改为/以前是 X 现在是 Y”式陈述——它写完就过期。
- 直接写现状：“当前用 X，原因是……”。发生替换时 **edit 原条目改写成现状**，不留两条对照。
- 发现过时条目 → 就地修正或删除，不追加“更正条目”。

## 5. 写前查重（强制）

- 写之前先在目标分片里查同 title / 同主题条目（工具 `save` 自动查重，同片同标题直接拒绝）。
- 同一件事已有条目 → **edit 补一句**（补充根因、补充适用边界），不新增重复条目。
- 同一事实在不同分片各写一条也算重复：保留更贴切的一片，另一片删掉。
- 查重关键词用：短标题、报错码、工具名、命令名。

## 6. 收工动作必须同一轮内完成

- 沉淀发生在**任务收尾的当轮**，不是“下次会话开头”——下次就忘了。
- 顺序：任务做完 → 判定（§1/§2）→ 查重（§5）→ 落盘（`exp-lite.mjs save` 或按格式 write/edit）→ 回报。
- 当轮写不完（如条目太多）→ 先写最值钱的 1~3 条，其余走兜底提炼（见 [pipeline.md](pipeline.md) 第 ③ 节），并在回报里说明。
- 共享文件写入纪律：**先 read 再写**；改条目用 edit 最小替换，不要整文件覆写（覆写会抹掉别人的条目）。

## 7. 回报格式（每轮末尾必带）

- 有沉淀：`本轮沉淀 N 条：<短标题1>、<短标题2>……`
- 无沉淀：`本轮无需沉淀`（并简述原因，如“纯问答，无可复用结论”）
- 兜底补录后：`兜底补录 N 条：……`
- 回报是给用户与父 agent 看的确认信号，**不能省略**，也不要用“已完成”糊弄。

## 8. 快速自检（落盘前 5 秒过一遍）

1. 这条换了项目还成立吗？（不成立 → 写项目层或不写）
2. 一条只讲一件事吗？标题能独立检索吗？标题带冒号了吗？（带了 → 去掉）
3. 有密钥/token/密码值吗？（有 → 改写成“凭据放在哪里”）
4. 同片已有同主题条目吗？（有 → edit 补一句）
5. 条目 ≤400 字吗？日期是今天的真实日期吗？
