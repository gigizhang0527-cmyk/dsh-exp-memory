# 经验沉淀全流程（开工 → 收工 → 兜底 → 体检，完整闭环）

> 四步闭环对应 [../SKILL.md](../SKILL.md) 的四步索引。每步给出：触发时机、动作、产物、常见错法。

## ① 开工先查（动手之前的强制动作）

**触发**：任何非琐碎任务的第一步。

**动作**：

1. 取任务关键词：框架名、工具名、文件名、报错码、命令名、用户原话里的名词。
2. 匹配索引：全局分片首行 `<!-- 片名 · 关键词… -->` 的关键词行 + 项目层 `projects/<slug>/MEMORY.md`。
3. 命中 → 按**行号** `read` 对应条目正文（只读相关条目或相关小节），再动手。
4. 没命中 → 直接开工。**不要整库通读，不要凭片名或标题臆测正文。**

**产物**：一份“已知约束清单”（命中的坑与做法），在动手时遵守。

**常见错法**：只看索引标题就下结论；开工后踩了已记录的坑；读了整库浪费上下文。

**细则**：索引只注入标题与行号（见 [data-model.md](data-model.md) §6），正文必须按行号读回。

## ② 收工沉淀（同一轮内落盘）

**触发**：任务收尾当轮，交付物做完、结论确定之后。

**判定**：见 [discipline.md](discipline.md) §1（值得记）/ §2（不值得记）；一票否决的红线见 §3。

**落盘（二选一）**：

```powershell
# 路 A：工具落盘（自动做凭据扫描 + 查重 + 格式）
node tools/exp-lite.mjs save --domain <领域key> --title "短标题" --insight "结论/做法/坑" ^
  --reuse "什么场景直接复用" --evidence "证据：文件或现象" --symptom "报错或检索关键词"
```

```markdown
<!-- 路 B：直接落盘（先 read 目标分片 → 查重 → edit 追加/补句） -->
- [2026-10-23] **短标题** —— 结论/做法/坑
```

- 领域 key 与分片对应：`network-env`、`dsh-platform`、`dsh-plugin`、`agent-method`、`office-docs`、
  `repo-research`、`video-pipeline`、`media-audio`、`video-hyperframes` 等；没有合适的就开新片
  （首行写 `<!-- <domain> · 关键词… -->`）。
- 项目专属事实写 `projects/<slug>/MEMORY.md`（索引行格式见 [data-model.md](data-model.md) §5）。
- 落盘后在回复末尾回报：**本轮沉淀 N 条**（格式见 [discipline.md](discipline.md) §7）。

**常见错法**：说“下次再记”；整文件覆写；同主题新增重复条目；把流水账当经验。

## ③ 兜底提炼（当轮漏记 / 会话超长时的批量补录）

**触发**：会话很长当轮没沉淀、任务被打断、或连续多轮产出未入库。

**动作（按成本从低到高）**：

1. **零 LLM 会话摘要**：会话日志是多帧 zstd（`session.v4.jsonl.zstd`），用现成 digest 流水线
   （`experience-kit` 的 `exp.mjs digest`）解压提取零成本摘要；拿到摘要后按 ENTRY 格式批量补录。
2. **当前 agent 自己总结**：回顾本会话已发生的踩坑、验证结论、取舍，逐条过
   [discipline.md](discipline.md) 的判定与红线，再批量 `save`。
3. 补录也走同样的查重（先读目标分片）与同样的格式；日期用**事件真实发生日**，不是补录日。

**产物**：补录条目 N 条 + 回报“兜底补录 N 条：……”。

**常见错法**：把整段会话原文贴进条目（流水账）；补录日期全写成补录当天；跳过红线扫描。

## ④ 体检拆片（定期 / 大量写入后）

**触发**：单片明显变长、注入索引出现 ⚠️超建议、或按周期（如每周/每 50 条）。

**动作**：

```powershell
node tools/exp-lite.mjs check   # 格式/日期/单条>400字/单片>12000字/重复标题
node tools/exp-lite.mjs index   # 打印片级行 + 条目标题与行号，复查命中率
```

1. **格式类问题**（日期非法、标题带冒号、单条超 400 字）→ edit 就地修正。
2. **重复标题** → 合并成一条（edit 补句），删掉重复。
3. **单片超 12000 字符** → 按**子主题拆片**：
   - 新片文件名 `exp-<domain>-<子主题>.md`，首行写新关键词注释；
   - 把相关条目**整条移动**过去（行号会变，注意引用）；
   - **原片与新片的首行关键词同步更新**（否则索引命不中新片）；
   - 拆完重跑 `check` + `index` 确认无重复、可命中。
4. 过时条目（变迁史式陈述）→ 就地改成现状或删除。

**产物**：体检报告（问题行 + 处理动作）+ 拆片后的干净索引。

## 常见坑（全流程通用）

- **写共享文件先 read**：直接 write 整文件覆写会抹掉别的会话/插件刚写的条目；改条目一律 edit 最小替换。
- **PowerShell 拼中文易乱码**：生成/写入含中文的文件改用 node / python 脚本（脚本内固定 UTF-8），
  不要用 PowerShell here-string 拼中文正文。
- **写前先查重**：同 title/同主题先查，命中就 edit 补一句；`save` 会同片查重并以 exit 3 拒绝。
- **凭据红线**：写入前八类模式扫描（`sk-`/`AKIA`/`ghp_`/`Bearer`/`password=`/`token=`/`passwd=`/`secret=`），
  命中拒绝写入，只写“凭据放在哪里”。
- **行号是引用地址**：条目一行一条；条目移动（拆片）后旧的行号引用要重查。
- **日期用真实发生日**：未来日期非法；补录用事件当天日期。
