# 数据模型规范（exp-memory 规格 §1 · 完整版）

> 本文件是插件 `dsh-exp-memory` 与 skill `exp-sedimentation` **共用**的数据层规格。
> 任何一方读写记忆库，都必须遵守这里的目录布局、首行注释格式、条目格式与 slug 规则。

## 1. 三层目录布局

```
<MEM>/                              # 记忆根目录
  topics/                           # ① 全局分片层：跨窗口、跨项目共享的经验片
    exp-<domain>.md                 #   每个领域一片，如 exp-network-env.md
  projects/                         # ② 项目层：只在对应工作目录下注入
    <slug>/MEMORY.md                #   索引 + 项目专属正文（slug 见 §4）
  settings.json                     # ③ 运行状态层：运行开关（插件自持，改完即生效）
  audit.log                         #   写入审计 JSONL（超 2MB 轮转 .1）
  distill-state.json                #   回合计数 / 冷却等提醒状态
```

- ① 全局分片层：领域无关、下一个项目还会用上的事实放这里；按 `<domain>` 分片，被跨会话注入索引。
- ② 项目层：出了这个项目就不成立的事实放这里；随当前工作目录（cwd）自动注入。
- ③ 运行状态层：插件自持的开关与审计文件，**不放经验正文**，也不要手改 audit.log（守卫会 deny）。

不同宿主的默认根目录（`<MEM>`）可以不同，工具与插件都支持显式指定根目录（exp-lite.mjs 用 `--root`）。
**写入前先确认当前根目录**，不要把 A 库的条目写进 B 库。

## 2. 分片首行注释格式

每个 `topics/exp-<domain>.md` 的**第一行**必须是：

```markdown
<!-- 片名 · 关键词1 关键词2 … -->
```

- 例：`<!-- network-env · 代理 Clash NAS IPv6 局域网 路径 -->`
- `片名` 与文件名一致（`exp-<domain>.md` 的 `<domain>` 部分）。
- 关键词会进入索引，是“要不要读这片”的唯一判断依据：写检索词（报错码、工具名、场景词），
  不要写形容词；新增子主题后**同步补关键词**。
- 首行注释之后再写正文；建议按主题分小节（`## 子主题`），但条目必须是 §3 的 ENTRY 格式。

## 3. 条目格式（ENTRY，守卫强制）

```markdown
- [YYYY-MM-DD] **短标题** —— 结论/做法/坑
```

示例：

```markdown
- [2026-10-23] **写共享文件先 read** —— 直接 write 会覆盖他人改动，先 read 再 edit 做最小替换。
```

硬性约束：

| 约束 | 要求 | 原因 |
| --- | --- | --- |
| 前缀 | `- [YYYY-MM-DD] `，日期为真实 ISO 日期，不允许未来日期 | 守卫与索引按此解析 |
| 标题 | `**短标题**`，**不带冒号**，能独立检索 | 索引按冒号截断标题 |
| 分隔 | `——`（两个破折号）后接结论 | 统一格式便于机器解析 |
| 长度 | 单条 ≤400 字符；超了先精简 | 注入预算有限 |
| 粒度 | 一条只讲一件事 | 便于按条检索与去重 |
| 行 | 一条一行，不写多行条目 | 行号即引用地址 |
| 史观 | 记现状，不记变迁史（不写“已卸载/不再使用”式陈述） | 写完即过期 |

- 同一件事已有条目 → **edit 补一句**，不新增重复条目。
- 长流程/长文档不要塞进条目：另存独立文件，条目里指向它（写清文件名即可）。

## 4. slug 推导规则（与会话目录名一致，Windows 安全）

```
路径反斜杠 → 正斜杠；盘符去冒号；非 ASCII 字符 → ~XXXX（4 位大写十六进制）；
`/` → `-`；两端加 `--`。
```

真实例子：

```
D:\Projects\机器学习  →  --D-Projects-~673A~5668~5B66~4E60--
```

逐段核对（“机器学习”四字的 Unicode 码点，大写十六进制）：

| 字 | 机 | 器 | 学 | 习 |
| --- | --- | --- | --- | --- |
| 码点 | U+673A | U+5668 | U+5B66 | U+4E60 |
| 转写 | `~673A` | `~5668` | `~5B66` | `~4E60` |

再举两例：

```
C:\Users\you\.dsh\memory          →  --C-Users-you-.dsh-memory--
D:\Projects\工具                  →  --D-Projects-~5DE5~5177--
```

实现要点：

- 非 ASCII 判定按**码点**逐字符转 `~%04X`；超过 U+FFFF 的字符按 UTF-16 码元各转一段。
- 大小写保留原样（盘符大写、文件名原样），只对字符做转写，不做小写化。
- slug 是路径的可逆表示，**不要手写**，一律用推导函数生成（插件 `lib/store.js` / exp-lite.mjs 同规则）。

## 5. 项目层 MEMORY.md 索引行格式

项目层 `projects/<slug>/MEMORY.md` 里，正文写在对应主题文件中，MEMORY.md 登记索引行：

```markdown
- [标题](文件名.md) — 摘要一句话
```

示例：

```markdown
- [通行费汇总单配平](toll-summary.md) — 以交易金额列配平，只改已拆分行。
```

要点：

- `[标题]` 用短标题，`(文件名.md)` 是同目录下的正文文件，`—` 后写一句话摘要。
- 正文文件本身仍用 §3 的 ENTRY 格式写条目。
- 直接写在 MEMORY.md 里的条目也必须是 §3 ENTRY 格式；索引行与 ENTRY 行不要混排在同一段落。
- 项目层条目一旦“出了这个项目还成立”，就升级写入全局分片层 `topics/`，并从项目层删掉（记现状）。

## 6. 与索引注入的关系（只读约定）

- 注入提示词的**只是索引**：片级行「片名 · N 条 · 体量 · 最新日期 · 关键词」+ 条目标题与行号。
- 正文永远按**行号**去 read，禁止凭索引标题臆测正文内容。
- 这就是 §2 关键词、§3 标题都要“能独立检索”的原因——索引是唯一的召回入口。
